# Evidence

Produced with REA 6.7.0 (`npm install --global rea-agents`) against `@openai/codex@0.163.0-linux-x64` (`vendor/x86_64-unknown-linux-musl/bin/codex`, SHA-256 `399ff69c431c066e40de318fba45c2b07f45a76b19939d247ee4828fc70c4215`) on 2026-10-22, in a Linux x86-64 sandbox with no route to OpenAI (every network call in the captures fails with a proxy 403; that is why no live rate-limit reading appears). The `OPENAI_API_KEY` in some scenarios is a dummy string, present only so the harness takes the API-key code path.

Limits of this evidence: no network, so no live `used_percent`, credits or thread estimates were observed, only their schemas and the strings that produce them; the binary is stripped and has no cargo-auditable section, so numbers computed in code (the auto-compaction default, the subagent concurrency default) were not recovered; REA's native decompiler providers (Ghidra, IDA, Hopper) were not available in the sandbox (their downloads are blocked), so analysis stopped at strings, headers and runtime captures.
